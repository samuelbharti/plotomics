# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

One name on every registry: `plotomics` on npm, on PyPI, on CRAN and on
r-universe. The three packages share a version and are released together from a
single tag. CRAN receives the R package by manual submission, so its version can
be behind the tag.

## [Unreleased]

## [0.3.0] - 2026-11-19

### Added

- The R package is on CRAN, published 2026-09-04 as 0.1.0. That release holds
  the R package as this section describes it: `bioprofile()` from 0.2.0, and no
  `igv()` or `gosling()`.
- `citation("plotomics")` returns the Zenodo DOI (R only).
- Every Shiny binding help page in the R package has an example, and so does
  `oncoplot_memo_sort()`.
- A "Getting started" vignette for the R package, `vignette("plotomics")`.
- A JavaScript API reference at <https://www.samuelbharti.com/plotomics/js/>,
  generated by TypeDoc, next to the R and Python references. The npm package
  names it as its homepage.
- A `padding` setting in the theme puts room around every plot: a number of px
  for all four sides, or `top`, `right`, `bottom` and `left`, 10 px by default.
  Axes, labels, legends and colour bars stay inside it, and the PNG and SVG
  exports keep it. R and Python check the value with the same error. (#211)
- `violin_aspect` in R and Python, `violinAspect` in JavaScript, caps the widest
  violin at that many times its row height, 0.8 by default. `NULL`, `None` or
  `null` turn the cap off. (#204)
- The network draws a legend of its node groups, with an NA entry for nodes that
  have no group, and its exports include it; `show_legend` turns it off. (#118,
  #205)
- The heatmap takes a colour bar title: `legend_title` in R and Python,
  `legendTitle` in JavaScript. (#122, #202)
- Python gains `upset_intersections()` and `violin_density()`, with the results
  R gives, and R `km()` takes `censor`, a data frame of censoring ticks, as its
  last argument, as Python `Km` does. (#122, #203)
- Embedding, heatmap, clustermap, Hi-C and treemap accept all four colormaps
  (`viridis`, `rdbu`, `ltc` and `ltcdiv`) in R and Python. (#122, #201, #202,
  #210)
- JavaScript: `autoResize(el, plot)` in `plotomics/core` follows the size of the
  element. The types that public signatures use (`Linkage`, `Metric`,
  `EmbeddingColorMode`, `NetworkLayout`, `AnyFactory`, `AnyModel`, `TypedArray`,
  `DomainScale`) are exported by name. (#90, #110, #203, #210)

### Changed

- Chart text takes its size from the theme font size (`theme$fontSize` in R,
  `theme["fontSize"]` in Python, `theme.fontSize` in JavaScript). At the
  default of 12, labels are 11 px, axis and legend titles 13 px and plot titles
  14 px; text was fixed at 7 to 13 px, mostly 9 px, and the font size changed
  nothing. Layouts measure their labels, end long ones with an ellipsis, and
  thin or shrink dense ones, so text stays inside the widget. (#112)
- Past 8 categories the default palette changes from Okabe-Ito to scanpy's
  20-colour cluster palette, so the 9th group no longer takes the colour of
  the 1st. KM, lollipop classes, oncoplot, profile and violin now take their
  colours from `theme$categorical`; they used Okabe-Ito whatever the theme said. A
  palette set in the theme is used as given. (#113)
- In R, each plot has its own default height, the one its Shiny `*Output()`
  and its Python class use: clustermap, dot plot, oncoplot, spatial and violin
  560 px, KM and UpSet 520, lollipop 440, profile 380 and the others 480. The
  clustermap height rises to 560 px in all three languages, and its colour bar
  moves to the right of the heatmap. (#111, #115)
- Clustermap `linkage = "ward"` is Ward's method on squared distances, as R's
  `ward.D2` and scipy's `ward`; it was `ward.D`, so Ward dendrograms change. R
  and Python warn when Ward is used with the correlation metric.
- Oncoplot annotation values are matched to samples by name. Unnamed values
  are read in the order of `samples`, and stop with an error when `samples` is
  not given. Genes rank by the number of samples altered, and a gene and
  sample altered in two or more ways show one "Multi-hit" cell, as maftools
  does.
- Python checks every choice that R checks with `match.arg` (colormaps and
  modes), so an unknown name raises `ValueError`; it reached the browser and
  drew a blank widget.
- JavaScript API: `niceMax` is no longer exported from the profile and UpSet
  modules, and `layoutUpset`, `layoutDotplot` and `layoutViolin` take label
  widths in px where they took a character count. `plotomics/core` adds
  `textSizes`, `textWidth`, `fitText`, `categoricalColors`, `PALETTE_20` and
  `compositePNG`.
- Gridlines sit under the data in every plot, on screen and in the PNG and SVG
  exports; they crossed the dots, points, bars, curves and confidence bands. A
  grid colour of "none", a transparent colour or one the browser cannot read
  draws no grid, and CSS variables resolve. (#102, #202, #206)
- Axes and colour bars label round values at their place, in one unit per axis
  ("0.8M, 1.0M", not "800k, 1.0M"), and float32 values from Python no longer add
  a step to an axis. (#101, #202, #207, #208)
- The embedding, network and spatial legends sit in a gutter right of the plot
  and no longer cover the data; a legend that cannot fit is left out. (#117,
  #118, #120, #202, #205)
- Heatmap and clustermap draw z-scores with `rdbu` when no colormap is given, so
  `colormap` defaults to `NULL` in R and `None` in Python. With a diverging
  colormap, a positive `vmax` or a negative `vmin` given alone is mirrored about
  0. (#123, #201)
- With more rows or columns than pixels, heatmap and clustermap draw the mean of
  the cells under each pixel; they sampled one row in several, so an outlier row
  could vanish. Zoom and pan draw from textures already built and pool the view
  once it rests. Past the GPU texture limit, a view that rests shows every row.
  (#133, #201, #209)
- Violins are at most 0.8 times as wide as their row is tall and never narrower
  than four times the label size; they came out flat and wide. (#204)
- Network node labels show from the starting zoom: the default `label_threshold`
  is 4, where it was 8. (#118, #205)
- Spatial takes its default spot diameter from the median distance between
  neighbouring spots, so neighbours touch; it was 4 image px. R and Python
  reject a given diameter that is not one positive number. (#120, #205)
- The lollipop count axis has round ticks with gridlines, decimal steps for
  frequencies, and a tooltip worded by `y_label`. Domains take a muted palette
  of their own, and `theme$categorical` colours the variant classes only;
  `domain_colors` still sets the domain colours. (#207, #208)
- Profile `as_fraction` must be one `TRUE` or `FALSE`, and stops when a value is
  negative. Values that are not finite are left out of the total, and negative
  bars go down from a zero line. (#167, #206)
- Oncoplot and lollipop classes, genes, samples and annotation levels break ties
  by name in code point order in R and Python, so the colours no longer depend
  on the locale R runs in. (#203)
- A plain JavaScript plot in an element with no height of its own gets a height
  of 480 px from a CSS rule that any page height overrides; it drew 480 px into
  a 0 px box. Plots fill the padding box of their element. (#110, #203)

### Removed

- `igv()` and `gosling()` left the R package, with their Shiny bindings:
  `igvOutput()`, `renderIgv()`, `goslingOutput()` and `renderGosling()`. The two
  bundles add up to more than 7 MB of JavaScript, which puts the installed
  package past the 5 MB limit that CRAN sets.

  This is a breaking change for R code that calls either function. The Python
  and JavaScript packages keep both components.

### Fixed

- The Python wheel ships the licence text. The package metadata declares the
  licence once, as PEP 639 requires, so newer build backends accept it.
- A missing value from R (`NA`, `NaN` and `Inf` reach the browser as `null`)
  or from Python (`None`, `NaN`, pandas `NA`) is shown as missing in every
  plot: a grey cell, an open ring, an "NA" legend key, or no mark. It used to
  be drawn as 0, take the low end of a colour scale, or blank the widget.
- PNG export (`exportPNG`, and `export("png")` in Python) holds the axes,
  labels, legends and colour bars, as the screen shows them; 13 plots exported
  the bare canvas. (#97)
- One-element vectors from R reach the browser as arrays, so a one-row data
  frame or a single class no longer breaks oncoplot, volcano, lollipop,
  heatmap, Hi-C, UpSet and network. An option left out on a re-render goes
  back to its default. (#95, #99)
- Hi-C draws its map in every browser; it was blank.
- Volcano: a p-value of 0 is drawn at the top of the plot, rows with a missing
  coordinate are left out, labels no longer overlap, and the theme background
  reaches the plot.
- Network: signed (negative) weights no longer stop the layout, edge widths
  scale to 1.7 to 6 px, and PNG and SVG export hold the graph.
- Treemap: draws without a value column, sums leaves only, and names its
  groups.
- KM: strata whose rows are interleaved, the risk-table order in R, the
  confidence band below the axis, and curves that stop before their last
  censored subject.
- Oncoplot and lollipop legends wrap, and lollipop variants at one residue
  stack on one stem, with labels kept clear of the heads.
- Dot plot and violin: missing values, and a value axis for each violin row
  (`show_value_axis`).
- Heatmap: matrices larger than the GPU texture limit, and crowded labels.
- Clustermap: clusters around missing cells and clusters again only when the
  data or a clustering option changes.
- Embedding and spatial: the colour type, the category order ("cluster 2"
  before "cluster 10") and lasso selections across re-renders.
- Profile, UpSet and lollipop axes put ticks on round values with exact
  labels, and long set names fit their column.
- IGV loads each track once and applies options that arrive before the
  browser is ready; Gosling frees its WebGL context on every update and on
  close.
- Python reads polars and pyarrow tables, and sends missing labels and groups
  as missing, not as the text "nan" or "None".
- Python sends big-endian arrays, as h5py and FITS give, with the right values,
  and the widget redraws when a new schema arrives after its buffers. (#108,
  #203)
- Python sends missing names, groups and labels as missing in every plot, as R
  does, and a polars LazyFrame stops with a message to call `.collect()`. (#195,
  #203)
- The clustermap paints its cells in the chosen colormap; only `rdbu` worked, so
  `ltc` and `ltcdiv` cells did not match the colour bar. (#133, #201)
- Hover lines up with the plot inside an element with a CSS border; ten plots
  read the pointer off by the border width. (#211)
- Every R Shiny example in the help runs as written. (#109, #200)

## [0.2.0] - 2026-08-14

### Changed

- **`profile()` is now `bioprofile()` (R only), with a `profile_plotomics()`
  alias.** Attaching the package used to mask the `stats::profile()` generic,
  which profiles a fitted model's likelihood. This mirrors what `bioheatmap()`
  already did for `stats::heatmap()`, and means `library(plotomics)` now masks
  nothing in base or the recommended packages. The Shiny bindings move with it:
  `profileOutput()` and `renderProfile()` become `bioprofileOutput()` and
  `renderBioprofile()`.

  This is a breaking change for R code written against 0.1.0. The Python and
  JavaScript packages are unaffected: neither language has the collision, so
  `Profile` and `createProfile` keep their names.

## [0.1.0] - 2026-08-09

First public release. Seventeen visualization components, each shipping from one
source bundle to JavaScript, R and Python.

### Added

- **Shared core (`plotomics/core`).** A single TypeScript core defining the
  component contract, theming, colour scales, binary column transport and export
  helpers, consumed by every visualization so behaviour stays consistent across
  languages. Includes the `viridis` and `rdbu` ramps plus the `ltc` sequential
  and `ltcdiv` diverging ramps. Ships as a subpath of the one npm package rather
  than a second package, so there is no version skew between core and components.
- **Tri-language wrapper architecture.** Each component ships from one source
  bundle to three targets: an npm package (`plotomics`), a Python
  [anywidget](https://anywidget.dev) widget (`plotomics` on PyPI, for Jupyter,
  JupyterLab, marimo, Colab, VS Code, Shiny for Python and Streamlit) and an R
  [htmlwidget](https://www.htmlwidgets.org) (`plotomics`, for the RStudio Viewer,
  R Markdown, Quarto and Shiny). Glob-discovered build entries let new components
  land without editing any central registry.
- **Binary column transport.** Numeric data reaches the browser as a binary
  buffer rather than JSON, which is what keeps hundreds of thousands of points
  interactive.

#### Expression and abundance

- **Volcano plot.** GPU-accelerated differential-expression scatter with
  significance thresholds.
- **Expression heatmap.** Large-scale WebGL expression matrix viewer.
- **Clustered heatmap (clustermap).** Heatmap with row and column dendrograms and
  hierarchical clustering.
- **Marker gene dot plot.** Features by groups, with dot area proportional to the
  fraction of the group expressing and colour carrying the level.
- **Stacked violin.** One row per feature, one violin per group, so a marker
  panel reads down the page. `violin_density()` computes the densities in R.

#### Single-cell and spatial

- **Embedding (UMAP/t-SNE) viewer.** GPU-accelerated scatter for single-cell and
  dimensionality-reduction embeddings. `aspect = "equal"` gives both axes the
  same units per pixel, for PCA scores and anything else whose axes share units;
  `point_scale_mode` chooses how points shrink as you zoom out; `padding` keeps
  the outermost points off the canvas border. A factor `color` column in R, or a
  pandas `Categorical` in Python, pins the legend order and colour assignment and
  keeps unused levels, the way `drop = FALSE` does in ggplot2.
- **Spatial tissue map.** Measurements at their real slide coordinates over the
  histology image, with the image and the spots sharing a single fit so they
  cannot drift apart on resize or on a high-DPI display.

#### Cohort and variant genomics

- **Oncoplot (OncoPrint).** The cohort alteration landscape: a gene by sample
  grid of categorical alteration classes, with a per-sample mutation-burden
  barplot, a per-gene frequency barplot and optional clinical annotation strips.
  `oncoplot_memo_sort()` produces the conventional column order.
- **Protein domain lollipop.** Variants along a protein over its domain
  architecture, with head area proportional to recurrence and an optional
  post-translational modification track.
- **Kaplan-Meier curve.** A right-continuous step function per stratum with
  censoring ticks, confidence bands and a number-at-risk table aligned to the
  same time grid. Accepts a `survival::survfit` object directly in R.
- **Categorical profile.** A grouped bar profile with coloured header blocks,
  built for the 96-context mutational signature layout and general enough for any
  ordered categorical profile that groups into runs.

#### Sets, hierarchies and networks

- **UpSet plot.** Set intersections as a bar chart over a membership matrix, for
  the many-set case where a Venn diagram is not drawable.
  `upset_intersections()` computes exclusive intersections, so the columns sum to
  the union rather than double-counting.
- **Gene treemap.** Hierarchical gene and category treemap.
- **Network graph.** Large-graph viewer built on
  [Sigma](https://www.sigmajs.org) v3 and
  [graphology](https://graphology.github.io), with directed edges, per-edge
  colour and drop reporting. In Shiny, clicking a node pushes its id to
  `input$<outputId>_selected`.

#### Genome and chromatin

- **Hi-C contact matrix.** WebGL contact-map viewer with level-of-detail tiling,
  for chromatin interaction data.
- **igv.js genome viewer.** Embedded [igv.js](https://igv.org) genome browser.
- **Gosling genome viewer.** Declarative genomics visualization via
  [Gosling.js](https://gosling-lang.org).

### Documentation

- [docs/motivation.md](docs/motivation.md) covers why the project exists, its
  non-goals, how it compares with ComplexHeatmap, maftools, survminer, UpSetR,
  Seurat and scanpy, and when to reach for one of those instead.
- [docs/architecture.md](docs/architecture.md) describes the component contract
  and the transport layer.
- Reference sites are generated per language: pkgdown for R, pdoc for Python.
